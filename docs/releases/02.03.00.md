# Kellmarks 02.03.00

## Settings and opt-in description defaults

Classification: **compatible feature release**, following the 02.02.01 packaging
fix. The Settings menu consolidates theme, JSON/browser-HTML import, JSON export,
remote-icon consent and a scoped browser-memory reset. The version remains in the
footer, not the header. Gold/black remains the default theme. Reset requires
confirmation, clears only Kellmarks-prefixed local/session storage, and never
writes to or deletes the server library or its backups.

A new session-only Settings option fills blank descriptions on **new** saves from
the linked public site's HTML metadata. It prefers `description`, then
`og:description`, then `twitter:description`, and stores at most 600 plain-text
characters. User-entered descriptions are preserved. Editing, importing, opening
a bookmark, searching and toggling the option never initiate a metadata request.
Consent is off on reload and unavailable in browser-only mode. Operator denial
(`KELLMARKS_EXTERNAL_REQUESTS=0`) overrides it on the server, not merely in the UI.

The compatible `POST /api/entries` option `fetchDescription: true` requests this
behavior explicitly. Missing/false preserves the old no-fetch contract. The
response remains an Entry with status 201; `X-Kellmarks-Description-Status` reports
the lookup outcome. Failure, unsafe targets and resource limits still save the
bookmark with a blank description. Normal validation/authentication/store-write
errors still fail normally. No bulk backfill or unsolicited rewriting is added.

## Security, limits and compatibility

Public HTTP(S) on default ports only; all DNS answers and every redirect are
validated. The socket connects to the checked numeric address, verifies the
actual peer, and HTTPS verifies the original hostname/certificate. Private,
loopback, link-local, multicast, reserved and IPv6 transition/translation targets
are denied. Redirects cannot downgrade HTTPS. No API tokens, cookies, referrers,
ambient proxies or third-party scraping services are used. HTML is parsed as
metadata only and rendered as text; scripts and page resources are not loaded.

Limits: six seconds overall per lookup, three redirects, 256 KiB HTML prefix,
four in-flight workers per process and 30 metadata attempts per client per minute
by default. Configure `KELLMARKS_METADATA_RATE_LIMIT` from 1 through 10000; existing
write limits also apply. Hung OS DNS resolution can occupy a bounded worker until
it returns, but cannot start a connection after the request deadline. No work is
queued, and no network call holds the private store's write lock. Logs include
request ID and status, never bookmark URLs, query strings or fetched descriptions.
These controls are application defenses, not a substitute for an egress firewall.

Schema **2**, existing API fields, import/export and authentication remain
compatible. No runtime dependency pins change. New configuration defaults do not
turn on automatic metadata fetching. CodeQL init/autobuild/analyze are updated
together to the immutable 4.38.2 revision already reviewed in PR #8.

## Validation and delivery

Regression coverage includes metadata precedence, malformed and hostile HTML,
DNS rebinding, mixed/private DNS answers, redirects, TLS verification, response
limits, deadlines, worker/rate saturation, preserving descriptions, no-network
edit/import paths, concurrent writes and failure-safe saves. Browser scenarios
cover Settings/reset, session consent, creation versus edits, text-only rendering,
double-submit prevention, failure fallback and operator/static-mode denial.

Run the full Python and JavaScript suites, lint/types, compilation, secret scan,
Bandit, release alignment and performance regression checks. The existing GitHub
CI gates additionally exercise Python 3.10/3.13, real Chromium, CodeQL, live
runtime/browser dependency audits and AMD64/ARM64 Docker deployments. Exact commit
and check outcomes are recorded in PR #15; publication remains gated on checks for
the exact main commit. Published source tags/images are not overwritten. Python
dependency audits and SBOMs are not a complete operating-system image scan.

This release advances selected work under #9, but does **not** complete the
remaining import-refinement, bulk/recovery, browser capture, collections, reading,
research, link health, offline or local-AI milestones. See the corrected
[roadmap delivery ledger](../ROADMAP.md).

## Upgrade and rollback

Read the [GHCR installation guide](../GHCR_INSTALLATION.md). Back up the private
library and `.env`; keep the same Compose project and persistent volume. After
02.03.00 has been published, select
`KELLMARKS_IMAGE=ghcr.io/paulkakell/kellmarks:02.03.00`, pull, and recreate:

```bash
docker compose -f docker-compose.yml pull
docker compose -f docker-compose.yml up -d --no-build --force-recreate --wait
```

Check authenticated health and the saved library, then reload the dashboard.
Metadata consent must be enabled again under Settings. To roll back, select the
previously published 02.02.01 image (or 02.02.00), pull and recreate with the same
commands. Existing schema-2 descriptions remain readable. No migration or reverse
migration is required. Never delete volumes (`down -v`) during upgrade/rollback.
No live server, DNS, certificate or operator data is changed by merging this PR.
