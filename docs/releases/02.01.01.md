# Kellmarks 02.01.01

## Dashboard update

This update implements favicon fallback, creation-only site tags, 20 theme presets plus custom colors, and a footer release check. The default gold/black palette and data schema 2 remain unchanged. No runtime dependencies or database migrations are added.

### Entry defaults

- A saved explicit icon URL always takes precedence. With no icon URL, the dashboard tries the bookmark origin's `/favicon.ico` over HTTPS. Bookmark paths, query parameters and fragments are never included. Sites that do not serve that conventional icon, or cannot serve it over HTTPS, fall back to initials.
- Remote images still require **Allow remote icons for this session**. The operator external-request deny switch overrides consent. No third-party favicon service or server-side arbitrary-site fetch is introduced; custom HTTP icons remain subject to the existing HTTPS image policy.
- A new entry with missing, empty or whitespace-only tags receives up to five local suggestions. Existing tags on the same normalized hostname are preferred, followed by bundled site rules, then `sites/<hostname>`. Suggestions do not fetch website metadata, invoke AI, or send bookmark data outside the application.
- Explicit tags are preserved. Editing, clearing tags, changing the URL, loading existing data, and importing bookmarks never regenerate tags. Static browser-local creation uses the same bundled rules.

### Appearance

Open **Theme** in the header. Choose one of 20 presets or customize page background, page text, accent, card background and card text. Changes preview immediately; **Apply theme** saves them in this browser, while **Cancel** or Escape restores the saved selection. **Gold / black** previews the original palette for restoration. A contrast warning helps identify hard-to-read custom combinations. Corrupt or blocked storage does not prevent the dashboard from starting.

### Release status

The footer shows the installed version and checks `/api/version` after successful API initialization. The server consults only the fixed public GitHub latest-release endpoint. It sends no API token, cookies or bookmark information, rejects redirects, uses a four-second upstream timeout and caps the response at 256 KiB.

Stable numeric version components are compared correctly, including zero-padded and `v`-prefixed tags. Status distinguishes current, newer available, development/ahead, no published release, unavailable and operator-disabled. Successes are cached per process for one hour; unsuccessful checks for five minutes. **Check again** reuses that bounded cache rather than bypassing it. The displayed timestamp is the actual last attempt, not the button-click time. Offline or malformed responses never claim that the installation is up to date. Static mode shows the running frontend version and a manual release link, without pretending to perform a live check.

`KELLMARKS_EXTERNAL_REQUESTS=0` disables the check before any network request. All existing API authentication and response protections apply. Health checks themselves remain network-free.

## Validation and compatibility

New regression tests cover creation versus editing/import, site-rule boundaries, manual tags, favicon URLs, all preset contrast ratios, preference validation, numeric release ordering, caching, malformed/oversized responses, privacy, authentication and operator denial. Real-browser scenarios extend the existing import/privacy suite with theme persistence, static-mode edits, favicon behavior, footer statuses and mobile layout.

Run `make validate` and `make browser` in a clean environment. Exact check outcomes and commit identifiers belong in the implementation pull request, not speculative release evidence here. This dashboard update does not claim delivery of the remaining roadmap milestones.

## Rollback

Back up the private JSON store, then restore the prior `02.01.00` release. Schema 2 is unchanged, so existing data remains readable. Automatically generated tags are ordinary stored tags and will remain until edited; rollback does not delete them. Theme preferences are browser-local and may be removed using the site's browser-storage controls.
