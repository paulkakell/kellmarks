# Kellmarks 02.01.02

## Monochrome monitors and clickable cards

Two new presets, **Monochrome green (1980s)** and **Monochrome amber (1980s)**, recreate a phosphor-monitor appearance with colored text on black, dark outlined cards, monospace typography and a subtle static glow. The logo and consent-enabled remote icons are tinted to match. There is no flicker, animation, downloaded font or additional network request. Choose either from **Theme**, then **Apply theme** to save it in this browser.

All 20 previous presets are retained (22 total), and gold/black remains the default. Preview, Cancel, Escape, custom colors, corrupt-storage fallback and saved preferences retain their existing behavior. Monitor-only typography and effects are removed when switching to another preset or custom colors.

Click anywhere in a bookmark card except its buttons to open the linked page in a new tab, matching the existing title link. This includes the icon, URL, description, card padding and gaps between buttons. **Edit**, **Delete** and tag buttons still perform only their existing actions. Delete still requires confirmation.

The implementation stretches the existing native title link rather than adding a JavaScript click handler or wrapping buttons in an anchor. There is one link tab stop per card, a visible whole-card keyboard focus outline, Enter activation, native middle/modifier-click and link context menus. The existing `noopener noreferrer` protection is retained.

## Validation and compatibility

The browser suite exercises actual pointer coordinates and touch navigation, tag/edit/delete isolation, keyboard tab order and Enter, middle-click, modifier-click, popup opener/referrer protections, all 22 themes, persistence and switching away from monitor styling. JavaScript regression tests cover additive preset IDs, palette contrast and saved-theme restoration. Existing server, security, privacy, import and release-metadata tests remain in place.

Run `make validate`, `node --test tests/frontend_enhancements.test.cjs` and `make browser` in a clean environment. Exact run outcomes and commit identifiers are recorded in the pull request after execution.

No runtime dependency, API contract, authentication, configuration default, private data or data schema changes are introduced. No database migration is required. The remaining roadmap milestones are not part of this update.
