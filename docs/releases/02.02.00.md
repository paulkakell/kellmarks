# Kellmarks 02.02.00

## Prebuilt GHCR installation

Classification: **additive feature release**, with release-pipeline fixes. The
version advances from 02.01.02 to 02.02.00 because this introduces a new
installation/distribution option. There is no breaking API or data-schema change.

Install the full server with the pull-only `docker-compose.yml` and
`ghcr.io/paulkakell/kellmarks:02.02.00`. Linux AMD64 and ARM64 are supported. The
image contains the existing dashboard, authenticated Flask API and Gunicorn;
no host Python, Git checkout or local image build is needed. The source-build
`compose.yaml` option remains available with a versioned local image default.
An explicit `KELLMARKS_IMAGE` override continues to take precedence.

Both Compose options retain the same project/volume names, mandatory API token,
loopback-only host port, non-root identity, read-only filesystem, capability
restrictions, healthcheck, logging bounds, request limits and optional Caddy
HTTPS overlay. Existing installations must preserve `.env` and the data volume.
Do not combine the two base Compose files. The new guide uses explicit `-f`
arguments to avoid Compose selecting the source-build file unintentionally.

Read the [GHCR installation guide](../GHCR_INSTALLATION.md) for Linux/macOS and
PowerShell instructions, private token generation, registry access, HTTPS,
configuration, digest pinning, upgrades, backup/restore and troubleshooting.
The [original installation guide](../INSTALLATION.md) remains the operational
reference and source-build/local-Python/static alternative.

## Release artifacts and publication

The release workflow now requires successful application, security, dependency,
CodeQL and Docker checks on the exact trusted main commit. Pull requests cannot
publish packages. A job-scoped `GITHUB_TOKEN` supplies registry credentials;
there is no new repository secret or personal token required for publishing.

Images carry version/source/revision OCI labels and build provenance/SBOM
attestations. The workflow tests the actual registry digest on AMD64 and ARM64
before promoting the version tag. Matching version/commit images are reused on
re-runs; mismatched revisions and authentication/network errors fail closed.
The optional `latest` alias moves only after a successful stable release while
main still matches. The default installation pins 02.02.00, not `latest`.

Downloadable installation assets include `docker-compose.yml`,
`.env.docker.example`, `compose.https.yaml`, `Caddyfile`, the installation guides,
`container.json`, `SHA256SUMS` and `kellmarks-02.02.00-docker.tar.gz`. The bundle
preserves the expected `docker/` and `docs/` paths. The explicit packaging
allowlist excludes `.env`, private libraries, backups and the source checkout.
`container.json` records the exact image digest and source commit.

**Initial GHCR visibility:** GitHub creates new packages as private. The package
owner must select Public in package settings for anonymous installation, or
users need authorized `read:packages` access. Publication records the anonymous
access probe separately; it does not silently alter permissions or claim a
private package is public. Actual public HTTPS issuance remains operator-owned.

## Validation and compatibility

New regressions cover isolated downloaded-file deployment, parity of security
and storage settings, version alignment, input validation, registry error
handling, immutable-image checks, multi-platform indexes, release gate ordering,
checksums and exclusion of private files from artifacts. Docker CI builds and
exercises both supported architectures, including missing-token denial,
health/authentication, private-path denial, persistence after recreation and
stopped-volume backup/restore. The existing Python/browser/security/performance
suite remains required. Exact outcomes and commit hashes are recorded in the PR.

Runtime Python dependencies remain pinned and unchanged. The two added Docker
setup actions are pinned to verified full commit SHAs and maintained through
existing Dependabot configuration. Build provenance identifies the resolved
base images. No database migration is required: schema 2, existing endpoints,
bookmark contents, authentication, theme preferences and editor behavior remain
compatible. No live installation, domain, private bookmark store or certificate
is modified by publishing this release.

## Rollback

Back up the library and `.env`, retain the currently working image digest and
matching Compose files, and use the same `kellmarks` project and data volume.
Set `KELLMARKS_IMAGE` to the retained prior digest and recreate with `up -d
--no-build --force-recreate --wait`, including the appropriate `-f` arguments.
Recheck authenticated health and bookmarks. Never use `down -v` for an upgrade.

02.02.00 is the first GHCR release; there is no promised 02.01.02 registry image.
For a pre-GHCR rollback, use your retained local image or the Docker source at
`7ac1982219fe023de308b4ad4171c47b7a0f33c9` (merged PR #13). The published
`v02.01.02` release at `0beb09de3b8faff4b6f1658103059198815ae1ad` remains available
for local Python rollback. Its source archive predates the Docker addition.
Schema-2 data needs no rollback migration. Existing tags/releases are not moved.
